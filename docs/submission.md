## プロジェクトの概要
AIの急速な発展はビジネスを劇的に効率化する一方で、たくさんのサイバー攻撃という深刻な脅威も生み出しています。「AIが脅威を生むなら、AIで守ればいい」。AIエージェントの活躍は、業務効率化だけではありません。AgentGuardは、マルチAIエージェントが連携してWebサイトを24時間見張り、攻撃を瞬時に検知・遮断して、やさしい日本語で報告する自律型セキュリティシステムです。AIの矛には、AIの盾を。AIが守る側に立つ新しい時代を、ここから始められると考えている。
### 対象ユーザー

- 個人や小さなお店・団体で、自分の Web サイトや Web アプリを運営している人
- Next.js（Vercel など）、Express、FastAPI でサイトを作れるが、セキュリティの専門家ではない人
- 「攻撃が来ているのか分からない」「来ても夜中は対応できない」「専用の WAF や監視サービスは高くて難しい」と感じている人

### 課題

1. **小さなサイトほど無防備**：SQL インジェクションや XSS などの攻撃は、規模に関係なく自動で飛んできます。それでも、小さなサイトには見張る人も仕組みもありません。
2. **見つけても対応できない**：WAF のログは専門用語だらけです。攻撃元の遮断や影響の確認は、専門知識と時間がないとできません。夜中や外出中は、なおさら無理です。
3. **AI に任せるのも不安**：AI にサイトの操作を任せると、だまされたり（プロンプトインジェクション）、やりすぎたり、同じ処理をくり返したりする心配があります。
4. **導入が難しい**：セキュリティ製品の設定は、手順が多くて分かりにくいです。

### ソリューションと特徴

AgentGuard は、**ルールで即座に止める WAF「ミハリ」** と、**攻撃を見つけたときだけ出動する AI エージェントのチーム** を組み合わせた、イベント駆動型の防衛システムです。すべて Google Cloud の Cloud Run の上で動きます。

**1. ふだんは軽く、攻撃の瞬間だけ AI が動く**
- サイトに届くアクセスは、サイトの処理より先に、すべてミハリが検査します（判定は約 0.1 ミリ秒）。攻撃と判断したアクセスは、その場で 403 で止まります。攻撃はサイトのコードまで届きません。
- 攻撃を見つけたときだけ、Pub/Sub 経由で AI チームが起動します。ふだんの AI 呼び出しは 0 回です。1 件の対応にかかる費用は、約 0.3〜0.5 円でした（実測）。

**2. 役割を分けた AI エージェントのチーム（ADK 2.x Workflow）**
- **番人**：Model Armor で、攻撃文に AI をだます命令（プロンプトインジェクション）が入っていないか調べます。
- **シラベ**：攻撃の種類・重大度・確からしさを分析します。
- **分岐**：防御・監視・見送りを、AI ではなくコードで決めます。
- **マモル**：攻撃元 IP のブロック、監視、サイト一時停止の依頼をします。
- **ツタエ**：専門用語を使わない、やさしい日本語で報告書を書きます。

攻撃を見つけてから IP をブロックするまで、約 3〜5 秒です。

**3. 安全に任せられるガバナンス（AI に任せきりにしない）**
- **道具の制限**：AI が使える道具は「守りを固める」ものだけです。解除の道具はありません。ブロックできるのは攻撃元の IP だけで、時間にも上限があります。
- **人の承認**：サイトを一時停止するときは、必ず人の承認が要ります。
- **AI の暴走対策**：AI の処理には、1 件あたりの道具の回数・時間・イベント数の上限があります。同じ操作のくり返しも防ぎます。
- **AI が止まっても守る**：AI が使えないとき（回数の上限・タイムアウトなど）も、コードの代わりの仕組みが 30 分ブロックします。
- **大量攻撃（攻撃の波）**：AI が同時に動くのは 1 アカウント 3 件までです。それを超えた分は、ルールで即座に止めます（30 件同時の攻撃でも、約 1.5 秒で全 IP をブロック）。
- **記録**：すべての操作は、監査ログに「だれが（AI か人か）・何をしたか」として残ります。

**4. 見える化（オブザーバビリティ）**
- ダッシュボードで、AI チームの考え・行動・結果をリアルタイムに実況します。
- 攻撃・操作・ログインの履歴を一覧できます。
- Cloud Trace で、インシデントごとの処理の流れを追えます。

**5. だれでもつなげる導入**
- サイトを登録すると、つなぐためのプログラム 1 つと、接続キーを保存したフォルダ（GitHub には送られず、外からも見えない）、サイトに合わせた手順書をまとめてダウンロードできます。
- Next.js はファイルを置くだけ、Express は 1 行、FastAPI は 2 行を足すだけです。
- Claude Code などの AI に作業を任せるための指示書も、同じフォルダに入っています。
- 「あなたのサイトかどうか」の確認は、キーそのものを外に出さない HMAC の答えで自動で行います。

**6. 自分の Gemini API キーも使える（BYOK）**
- 利用者の API キーは Cloud KMS で暗号化して保存します。1 日の上限は利用者が決められます（上限なしも可）。
- デモモードは、プロジェクトの Gemini（Agent Platform）で動きます。

**7. AgentGuard 自身も守る**
- このダッシュボードへのアクセスも、同じミハリと AI チームで守っています。守りの状況は、だれでも数で確認できます。
- くわしい記録と操作（ブロック解除・許可リスト）は、管理者の 1 アカウントだけが使えます。

### 使っている Google Cloud の技術

- **アプリ実行**：Cloud Run（dashboard / target＋WAF / agent の 3 サービス）
- **AI**：Gemini（Gemini Enterprise Agent Platform）、Agent Development Kit（ADK 2.x Workflow）、Model Armor
- **そのほか**：Pub/Sub（イベント駆動・DLQ）、Firestore、Cloud KMS、Firebase Authentication、Cloud Trace / Cloud Logging
- 各サービスは、専用の最小権限のサービスアカウントで動きます。

## 動作確認の方法（審査用テストアカウント）

- **ログイン方法**：メールアドレスとパスワード（トップページの「メールでログイン」）
- **メールアドレス**：`judge@agentguard.demo`
- **パスワード**：（お手元のパスワードを記入）

**確認の手順**
1. ログインすると、ダッシュボードが開きます。
2. 右側の **「攻撃シミュレーター」** のボタンを押してください。本物のサイトには何も送らず、見本の攻撃イベントを AgentGuard に流します。
   - 1 件ずつ：数秒で、AI チーム（番人 → シラベ → マモル → ツタエ）が調べて IP をブロックし、報告書を書く様子が実況されます。
   - 「5 件」「30 件」：同時の大量攻撃（攻撃の波）を、AI とルールで分担して止める様子が見られます。
3. **「履歴」**：これまでの攻撃・操作・ログインの記録が見られます。
4. **「守るサイト」**：自分のサイトを登録してつなぐ手順（4 ステップ、フォルダのダウンロード）が見られます。
5. ダッシュボードの **「このサイト（AgentGuard）自身も、AIチームが守っています」** のカード：このサイト自身への本物のアクセスを検査した数・止めた数が見られます。

**補足**
- このアカウントの AI 解析は、1 日 50 回まで使えます（それを超えても、ルールでの防御は続きます）。
- Google ログインは使わなくても確認できます。
